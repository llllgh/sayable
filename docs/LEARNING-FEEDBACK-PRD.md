# Sayable 教学反馈与重答闭环需求

版本：v1.0

日期：2026-09-11

状态：实施中（M1 评分下线已完成；转写修订、F2、F3 待实施）

适用平台：Android 与 Web 共用学习流程

## 1. 目标与范围

本次只实施以下三项：

1. 撤掉缺乏可靠依据的语音评分。
2. 允许原句不改，明确区分必要纠错与可选优化。
3. 把反馈后的脱稿重答做成主要交互，区分首次表现与反馈后表现。

目标是让用户获得可信反馈，并在看过反馈后亲自完成一次新的产出。验收以本文中的行为和案例为准；不把单元测试通过等同于学习效果已得到验证。

本文是现有 PRD 的专项补充。如果旧文档中的语音评分、强制诊断、必须提炼骨架或反馈后直接结束等规则与本文冲突，在上述三项范围内以本文为准。

本次不调整首页推荐数量、不重做复习间隔、不更换掌握算法、不新增听力课程或独立随机情境入口，也不引入语音实时对话、发音评测服务或完整语法课程。

## 2. 当前问题

| 编号 | 当前行为 | 问题 |
| --- | --- | --- |
| F1 | 用识别文本与骨架的差异计算“可懂度”，用语速、停顿、词时长等启发式计算总分和节奏 | 正常填充多个词可能得低分，不能据此判断实际口语质量 |
| F2 | 改写时倾向于必须找病症、压缩并提炼新骨架 | 正确表达也可能被改动；可选风格优化容易被呈现为纠错，甚至损伤原意和承诺边界 |
| F3 | 展示反馈后以“完成”为主；压缩后主要邀请收编骨架 | 用户可以只阅读建议就离开，没有完成对同一任务的主动修正与脱稿输出 |

## 3. F1：撤掉误导性语音评分

### 3.1 展示要求

- 所有学习页面停止展示当前语音总分，以及“可懂度、完整度、流利度、节奏”四项数值评分。
- 停止展示由这些算法生成的“语速偏慢”“整体清楚”等口语质量结论；不能仅将百分数改成等级、颜色或星级后继续使用。
- 当前启发式评分不参与通过判定、复习调度、掌握状态或重答是否完成的判断。
- 保留语音输入、文字转写、已有朗读能力。没有语音输入条件时仍可打字练习。
- 录音时长等确实采集到的事实可以保留为普通信息；缺失时不显示，也不能补零后推断能力。无需为替代旧分数新增仪表盘。
- 本需求只撤掉语音启发式评分；文本判卷中的正确性、语义和任务完成反馈继续保留，并遵循 F2。

### 3.2 转写核对

1. 识别出的文字显示在可编辑输入区，提交前用户可以修正识别错误。
2. 不为每次录音增加强制确认弹窗，继续使用当前“检查输入后提交”的路径。
3. 提交后若用户发现转写错误，提供次级入口“识别有误，修改文字”。修改后重新评估同一尝试，不重复推进或回退复习进度。
4. 保存原始转写与用户确认后的文本，记录发生过转写修订。修订后的结果标注为经过编辑，不记作未经修改的口头输出证据。
5. 识别失败、空文本或服务异常属于技术状态，不自动算用户答错。

### 3.3 历史兼容

- 已有学习数据与历史评分字段可以保留，但旧评分在用户界面中不再作为能力评价展示。
- 不因评分下线重置已有条目或复习进度。
- 本次不新增原始录音长期保存；保持现有音频隐私和存储策略。

### 3.4 验收

- Android 和 Web 的语音答题结果均无旧总分、四项分数及其衍生等级。
- 以下文本均不会产生上述语音评分，也不会因为与骨架文字长度不同而影响语言判卷：
  - 目标：`My only concern with X is that Y.`
  - 回答：`My only concern with changing the vendor now is that it might delay our timeline by two weeks.`
- 转写修改后可重新提交；一次尝试只产生一份最终有效判定和至多一次调度结果。
- 麦克风不可用时可继续文字练习；ASR 失败不扣学习进度。

## 4. F2：允许原句不改，区分纠错与优化

### 4.1 反馈分类

对用户提供的英文表达，语言反馈必须落入以下一种状态：

| 状态 | 适用条件 | 展示与动作 |
| --- | --- | --- |
| 原句可保留 | 原句准确、清楚，没有明显必须处理的问题或值得展示的优化 | 显示“这句已经清楚，可以直接用”，保留原句；主动作“完成”，次动作“脱稿再说一次” |
| 需要修正 | 存在实质语言、语义或任务相关问题 | 显示一个主要问题与最小修正版；主动作“我再说一次”，次动作“稍后再练” |
| 可选优化 | 原句可接受，但存在明确、有收益的精简或组织方式调整 | 先说明“原句没错”，再给至多一个可选版本；主动作“练习这个版本”，次动作“保留原句并完成” |

补充规则：

- 有必要纠错时，优先进入“需要修正”；可选风格建议不与主要错误争夺注意力，默认折叠或省略。
- 语言反馈与专项练习是否用到目标骨架分别判断。句子本身正确但没完成题目时，明确说明“表达本身没问题，本题尚未完成……”，不能编造语法错误。
- 中文译写仍提供英文译文；“原句可保留”不用于把中文当成已合格的英文答案。
- 听到的表达仍可解释用法；无需为没有问题的表达制造诊断。

### 4.2 语义和分寸要求

所有改写、精简、判卷修正和会前建议都必须遵守：

- 保留原文的事实、主体、否定、时间、范围、条件、责任与不确定性。
- 不将可能性改成保证、建议改成决定、讨论改成执行承诺。
- 不将更强势的语气默认视为更专业；不将短条件句或多个短句默认视为松散。
- 不因大小写、ASR 标点或单纯的同义词偏好判错。
- 有效的小语法修正仍可与“任务通过”并存，不把所有局部错误升级为阻断性问题。
- 不将用户未提供的产品性能、可靠性或业务事实写成确定断言。示例中确需假设时，显式说明假设。
- 精简以保留意思为前提；15 秒或特定字数只作建议，不强迫删除重要限定条件。

模型返回“无需修改”是正常成功结果。不得因没有诊断、短版或新骨架而重试请求。

### 4.3 学习条目准入

反馈和新增条目是两个独立决定：

- 允许不创建新骨架；`primary`、诊断及可选短版应能为空。
- 已有条目能够覆盖本次内容时，优先关联并练习该条目，不强制生成另一条“新东西”。
- 原句可保留，不代表禁止用户自愿收录；但完成当前操作不能以收录为前提。
- 没有新骨架时，不显示空的骨架卡片、入库按钮或首次骨架练习题。
- 模型的长表达不合格式时，校验失败或重新生成；不能截成前七个词后当作学习材料。

### 4.4 数据与模型契约

采用以下逻辑字段，具体命名可与现有结构对齐：

- `feedbackKind`：`keep / correct / optional`。
- `mainIssue`：一个主要问题；没有则为空。
- `correction`：必要修正版；没有则为空。
- `alternative`：一个可选优化版；没有则为空。
- `admission`：`none / reuse / new`；复用时携带有效已有条目 ID，新建时才携带骨架数据。

确定性校验必须保证：`keep` 不带必须修改的错误说明；`correct` 有具体问题与修正版；`optional` 不判原句为语言错误；`none` 不触发入库；`reuse` 不接受不存在的条目 ID。

旧数据没有分类字段时，不批量重新请求模型。可显示既有原文和建议，并标注旧记录未区分纠错与优化；不能自动推断旧建议都是必须纠正的错误。

### 4.5 真实模型回归案例

以下案例检查行为，不要求模型逐字复现某个标准答案：

| 输入或条件 | 必须满足 |
| --- | --- |
| `We can start with a small pilot. If the results meet the agreed criteria, we can discuss a wider rollout.` | 接受原句；不得把 discuss 说成缺点，不得删去“再讨论”的决策边界 |
| `This may reduce latency, but we need to validate it under your workload.` | 保留 may、验证要求和用户负载条件，不改成确定效果 |
| `We didn't deployed the update yesterday.` | 只需纠正为 `We didn't deploy the update yesterday.`，解释 did 后用原形 |
| `Could you clarify how does the workflow handle failures?` | 最小修正为 `Could you clarify how the workflow handles failures?` |
| 与正确参考句仅大小写和标点不同 | 不判为语言错误，不生成无意义纠错 |
| 已有骨架能覆盖本次意思 | 可以复用旧条目或零新增，不强制生成新骨架 |
| 内容包含多个必须保留的限定条件 | 允许超过建议长度，不以压缩率换取信息缺失 |
| 只提供“客户询问 AI 能否保证答案正确” | 不自行声称当前产品已能可靠处理某类业务 |

## 5. F3：反馈后脱稿重答

### 5.1 覆盖入口

| 入口 | 重答对象 |
| --- | --- |
| 首次造句、普通复习、推荐练习、会前骨架练习 | 当前同一道题 |
| 添加表达中的英文改写、中文译写 | 用户本次要表达的原始意思，无需先入库 |
| 精简表达 | 原始段落的核心信息和限定条件；不替换成另一道骨架造句题 |
| 两轮情境对话反馈 | 需要调整的一个用户回合；保留该回合前的对话背景，作为独立重答，不追加第三轮客户对话 |

### 5.2 主流程

```text
首次提交或查看答案
  → 看到一个主要反馈
  → 点击“我再说一次”或“练习这个版本”
  → 隐藏参考内容，保留题目和必要背景
  → 用户重新说出或输入答案
  → 提交并检查
  → 完成，或再练一次／稍后再练
```

“原句可保留”时允许直接完成，重答为次级动作，不强迫用户为了结束操作重复已经合格的表达。

### 5.3 重答界面

- 仍在当前题目中，不跳回首页、不抽下一题、不重新生成情境。
- 清空输入区，不自动填入 AI 建议或用户上一版答案。
- 隐藏英文骨架、参考例句、纠正后的答案、精简版，以及含答案的解释。暂停尚在播放的答案朗读。
- 保留必要题面和客观背景。压缩任务保留简短的中文内容要点，用户可按需查看原文。
- 对话重答保留该回合之前的对话，不展示其后的原始追问作为提前提示，也不展示被重答的旧答案。
- 主输入提供语音与文字，使用者选择方式；无法语音输入时可继续文字练习。
- 提供次级动作“再看提示”。展开后本次标记为使用过提示；再次隐藏不能将该记录清零。
- 页面可以写“先不看参考，用自己的话再说一次”，不得把这次尝试称为未经学习的首次独立回答。

### 5.4 重答评价

- 优先检查本次主要问题是否处理、原意及限定条件是否保留、表达是否可理解。
- 不要求背诵 AI 原句。不同措辞只要满足任务要求即可。
- 专项骨架练习仍沿用目标骨架要求；压缩和原意重述按信息与表达判断，不强制使用新骨架。
- 第二次反馈不因用户换了正确措辞又产生新的风格修改清单；其他问题只在影响理解或原意时提示。
- 通过后显示“这次已经说清楚了”，主动作“完成”。
- 未通过时只指出最重要的剩余问题，提供“再练一次”和“稍后再练”。默认邀请一次重答，单个任务最多接受两次有效重答；达到上限后以“稍后再练”为主，避免无限精修。
- API 重试、转写修订不消耗有效重答次数。

### 5.5 记录与复习调度

首次尝试与反馈后重答必须关联，但不能相互覆盖：

- 保留 `sessionId`、来源入口、关联条目或原文 ID、题目/背景快照。
- 每次尝试记录：顺序、阶段（首次／反馈后）、输入方式（语音／文字／未知）、原始转写、确认文本、是否修订、提示使用、判分来源、结果和时间。
- 原有不完整历史标记为未知，不补造“无提示”“语音”或“独立作答”证据。
- 普通复习的正式调度结果仍由首次有效尝试决定，沿用现有通过、失败与查看答案规则；同一会话的反馈后重答不再调用一次升降阶。
- 首次未通过、重答通过时显示“已完成修正，下次再独立练一次”，保留首次失败对应的复习安排。不能将两个结果计成两次正式召回。
- 首次通过但有小错时，保留首次通过结果；重答只补充修正记录。重答失败也不额外降阶。
- F1 中的转写修订视为替换同一次有效判定：若此前已应用调度，必须从该次尝试前的状态重新计算一次，不能累加应用。
- 原文改写、压缩或翻译尚未关联学习条目时，重答只保存练习记录，不自动创建条目或复习计划。
- 情境对话保留原来的两轮结果；反馈后的局部重答不改写原对话，也不再推进一次条目进度。
- 任何练习和重答都不自动增加“真实使用次数”。

### 5.6 中断与失败

- 点击“稍后再练”可以正常退出，保留已提交的回答和反馈，不追加一次失败。
- 进入后台或切换页面时停止麦克风，保留当前重答草稿；返回同一未结束会话可继续。
- 模型超时或网络失败时保留答案，提供重试、稍后继续；不能把服务故障判为语言错误。
- 自评必须标注判分来源，不伪装成模型确认。未确认的请求不改变调度。
- 提交期间防止连点重复请求；响应到达时若用户已离开，不抢占当前页面。
- 在“查看答案”之后点击“再练一次”，必须在当前题目进入空白重答，而不是调用完成回调跳走。

| A08 | 修正提交后的识别错误 | 替换同一尝试的有效文本与判定，调度不重复累加 |
| A09 | 精简结果后进入重答 | 重述原文核心信息；没有入库也可练；不按字数比例判通过 |
| A10 | 对话结束后练习一个回答 | 使用原回合之前的背景；不生成第三轮客户发言，不重复计算对话成绩 |
| A11 | 查看答案后点击再练一次 | 原地重答，答案隐藏；不跳到下一题 |
| A12 | 网络失败、退出再返回、连续点击提交 | 内容不丢；无技术性误判、重复记录或重复调度 |

## 7. 实施位置与交付检查

建议按现有结构修改，避免更换框架：

| 范围 | 主要实现位置 |
| --- | --- |
| 语音转写 | `src/speech/types.ts`、`src/speech/cloud.ts`、`js/speech.js`、`js/views.js` |
| 提示词、nullable 输出、反馈分类 | `js/llm.js`、`src/llm/schemas.ts`、`src/core/judgement.ts` |
| 普通练习和添加表达的重答 | `js/views.js` |
| 精简与会前练习 | `js/views2.js`、`src/core/compressions.ts` |
| 对话后的局部重答 | `js/roleplay.js`、`src/core/roleplay.ts` |
| 尝试记录、幂等调度、旧数据兼容 | `js/store.js`、`src/storage/state-migrations.ts`、`src/storage/backup.ts` |

建议交付顺序：F1 撤掉误导反馈 → F2 调整模型和展示契约 → F3 接入重答及记录。每项均需通过对应验收，三项完成后再进行整体验收。

实施完成时必须提交：

- 三项功能的实现和与现有 PRD 冲突部分的同步更新。
- 反馈分类、空骨架分支、尝试记录、转写修订、重复提交和调度幂等的必要自动化测试。
- 第 4.5 节的真实模型回归记录，注明测试时间、模型及通过/失败结果；一次通过不宣称全面可靠。
- Android 实机或模拟器与 Web 的第 6 节走查结果，语音至少覆盖一次实际录入及转写修订。
- 旧数据加载与备份恢复验证，确认不会把历史未知记录升级成独立口语成功。

本次需求的完成标准是：用户不会再收到误导语音分数；已合格表达有明确保留出口；需要修正时可以在原题中隐藏答案重答，且不会通过重复练习虚增正式成绩。
